# A/B 测试设计与效果评估

> **数据为脚本模拟生成，实验分析方法为真实实现。**

## 项目简介

从「结算页改版」这一实验假设出发，完成「实验设计 → 随机性校验 → 主指标检验 → 分群下钻 → 决策建议 → 陷阱复盘」的完整实验分析链路。

这个项目与「画图 + 算转化率」的差异在于**统计功底**：它回答的不只是「有没有效果」，而是「这个结论为什么可信」——样本量够不够、随机化有没有问题、p 值之外效应量和置信区间是什么、分群结论会不会是多重比较的偶然、反复偷看数据会不会放大假阳性。

技术栈：Python + scipy（统计检验）+ pandas + matplotlib + SQLite（SQL 交叉验证）。

## 实验设计

- **假设**：把结算页从「单页表单」改为「三步引导式」，是否能提升支付转化率？
- **分组**：对照组 `control`（旧版单页）vs 实验组 `treatment`（新版三步引导式），50/50 随机分流。
- **主指标**：支付转化率；**辅助指标**：转化用户人均支付金额（客单价）。
- **样本量怎么定**：用两比例 z 检验的样本量公式，在基线转化率 8%、最小可检测效应 MDE=1pp、α=0.05、power=0.8 下，反推每组需 **12208** 人、共 **24416** 人，预计实验 **14 天**（详见 `src/design.py` 的公式推导与 `reports/figures/power_curve.png`）。

## 分析流程

按「**校验 → 主指标 → 分群 → 陷阱**」的顺序，每一步都在为「结论可信」加一道保险：

1. **随机性校验**：先验证分流是否干净（SRM + 分流前指标平衡 + 分组构成）。随机化有问题，后面全部作废；
2. **主指标检验**：转化率（两比例 z 检验）+ 人均金额（正态性/方差齐性判断后选检验），给出效应量、置信区间、p 值；
3. **分群下钻**：按设备、新老用户拆分，看整体效应是哪些人群带来的；
4. **陷阱复盘**：演示 peeking（偷看数据）与多重比较两类常见错误，量化其假阳性风险。

## 核心结论

- **转化率显著提升**：control 7.96% → treatment 9.71%，绝对提升 **+1.74pp（相对 +21.9%）**，95% CI [1.03, 2.46]pp。
- **客单价小幅提升**：转化用户人均支付金额 +2.00%，bootstrap 95% CI [1.30%, 2.68%]。
- **收益分布不均**：新用户（+2.72pp）与 iOS/Android 端（+1.2~+2.6pp）是主要受益人群；**Web 端（+1.00pp）与老用户（+0.29pp）未观察到显著提升**。
- **随机化有效**：SRM 与分流前指标平衡性全部通过。

## 决策建议

**分阶段、分人群上线**：先在新用户 + iOS/Android 端全量切换新版结算页（收益最确定）；Web 端与老用户暂缓，继续观察或单独优化。

## 方法说明与取舍

> 这一节是面试官最关心的：每个检验「凭什么这么选」。

1. **为什么转化率用两比例 z 检验**：转化率是比例指标，样本量上万，二项分布可用正态近似；z 检验比卡方检验能直接给出方向与效应量的置信区间。
2. **为什么用双侧检验**：我们只关心「是否有差异」，不预先假设新版本一定更好（保守、可复现），故取双侧 α=0.05。
3. **为什么金额用 Mann-Whitney U**：金额是右偏分布，Shapiro-Wilk 拒绝正态假设，t 检验的前提不成立；Mann-Whitney U 是非参数检验，不依赖正态假设，只用秩信息。
4. **「人均支付金额」怎么定义**：取「转化用户」的客单价，而非全员平均（含 0）。理由：转化率已单独作为主指标，金额指标应隔离「金额本身」的效应（+2%），否则会被转化率效应（+22%）掩盖；这一选择会带来选择偏差（实验组转化了更多边缘用户），已在报告局限中说明。
5. **α 与样本量怎么取**：α=0.05、power=0.8 是行业惯例；MDE=1pp 是「业务上值得投入改动的最小提升」。样本量由公式反推，而不是拍脑袋。
6. **分群结论的多重比较**：设备/新老用户是预指定的次级假设，不校正；城市等探索性分群需用 Bonferroni/FDR 校正（详见 `src/pitfalls.py` 与 [docs/decisions.md](docs/decisions.md)）。

## 局限与后续实验建议

- 观察期仅 14 天，未覆盖长期留存与复购，建议延长观察或做滚动窗口复查；
- 金额结论基于转化用户，存在选择偏差；
- 分群为探索性分析，城市维度等存在多重比较风险；
- 数据为模拟生成，效应量是「为演示分析流程而设计」的，不能外推为真实业务收益。

> 数据生成所用的「真实效应」设定见 [docs/decisions.md](docs/decisions.md)，README 不剧透，让分析流程自己去发现结论。
