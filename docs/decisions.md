# 方法选择记录

统计方法为什么这么选，以及数据埋的「真相」（这些只写在这里和代码注释，README 不剧透）。

## 数据真相（评审对照用）

- 每组 12208 人、共 24416 人（由功效分析反推）
- control 转化率约 8.0%，转化用户客单价约 ¥120
- 埋的真实效应：整体转化率 +约 1.7pp、客单价 +约 2%；iOS/Android 约 +2.0pp、Web 约 +0.3pp、新用户约 +2.5pp、老用户约 +0.6pp
- 转化由二项抽样提供噪声，金额是对数正态（σ=0.08）并在组内中心化，让 +2% 精确落地

## 1. 为什么转化率用 z 检验 + 双侧（重点）

比例指标 + 大样本，二项分布能正态近似，z 检验直接给效应量和置信区间。取双侧是因为只关心「有没有差异」、不预设新版本一定更好，更保守。要是事先有强方向性证据才用单侧。

## 2. 为什么金额用 Mann-Whitney U（重点）

金额右偏，先做 Shapiro-Wilk 正态性 + Levene 方差齐性，结果非正态，所以选 Mann-Whitney U（非参数、只比秩、不依赖正态假设），比硬套 t 检验稳。

## 3. 样本量怎么定的（重点）

α=0.05、power=0.8 是惯例，MDE=1pp 是「业务上值得改版的最小提升」。套两比例样本量公式：

n = [Z_{α/2}·√(2p̄(1-p̄)) + Z_β·√(p0(1-p0)+p1(1-p1))]² / (p1-p0)²

算出来每组 12208 人，和 gen_data.py 对得上。

## 4. 「人均支付金额」口径

取转化用户的客单价（`mean(amount | converted=1)`），不是全员平均。因为转化率已经单独做主指标，金额指标要隔离「金额本身」的 +2%，不然会被转化率的 +22% 盖掉。代价是有选择偏差（实验组转化了更多边缘用户），所以金额结论和转化率结论分开解读。

## 5. peeking 和多重比较（加分项）

- **peeking**：定义为「按天累计、每天测一次、p<0.05 就停」。蒙特卡洛模拟一个无真实效应的实验，实测假阳性率约 21.9%（远高于名义 5%），说明反复偷看会放大第一类错误。
- **多重比较**：设备/新老用户是预指定的次级假设不校正；城市是探索性分群，12 次检验「至少一次假阳性」概率 46%，必须 Bonferroni / FDR。实测 3 个城市「偶然显著」，校正后全被剔除。

## 6. SRM 阈值为什么取 0.001

SRM 是分流机制的硬检查，漏过等于实验作废，用更严的 0.001；平衡性检查用常规 0.05 就行。
