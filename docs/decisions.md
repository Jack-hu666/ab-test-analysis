# 方法选择与数据设计记录

本文记录本项目每个统计方法的选择理由，以及数据设计的「真相」（这些只写在这里与代码注释，README 不剧透，让分析流程自己去发现结论）。

## 1. 数据设计的真相（仅供评审对照）

- 规模：每组 12208 人、共 24416 人，由 Step2 功效分析反推。
- 基线：control 转化率约 8.0%，转化用户客单价约 ¥120。
- 真实效应（数据生成时埋入，分析应能检出）：
  - 整体转化率：treatment 提升约 **+1.7pp**（相对 +20% 左右）；
  - 转化用户人均支付金额：treatment 提升约 **+2%**；
  - 分群差异：iOS/Android 端约 +2.0pp（显著）、Web 端约 +0.3pp（不显著）；
    新用户约 +2.5pp（显著）、老用户约 +0.6pp（不显著）。
- 噪声：转化由二项抽样提供波动；金额为对数正态（σ=0.08）并在组内中心化，
  使「+2%」的金额效应在设计上精确落地（避免固定种子下抽样波动稀释效应）。

## 2. 为什么转化率用「两比例 z 检验」+ 双侧

- **决策**：主指标转化率用两比例 z 检验，双侧 α=0.05。
- **理由**：比例指标 + 大样本，二项分布可用正态近似；z 检验能直接给出效应量与置信区间。取双侧是因为只关心「是否有差异」、不预先假设新版本一定更好，这是更保守、可复现的选择（若事先有强方向性证据，可用单侧）。

## 3. 为什么金额用 Mann-Whitney U

- **决策**：金额先做 Shapiro-Wilk 正态性检验与 Levene 方差齐性检验；结果非正态（右偏）→ 选 Mann-Whitney U。
- **理由**：金额是典型右偏分布，t 检验的正态假设不成立；Mann-Whitney U 是非参数方法，只用秩、不依赖正态假设，对偏态数据更稳健。

## 4. 「人均支付金额」口径 = 转化用户客单价

- **决策**：金额指标取「转化用户」的客单价（`mean(amount | converted=1)`），而非全员平均（含未支付 0）。
- **理由**：转化率已单独作为主指标（+22%），金额指标应隔离「金额本身」的效应（+2%），否则全员平均会被转化率效应淹没，无法回答「新结算页是否让付费用户花更多钱」。
- **代价**：存在选择偏差——实验组转化了更多「边缘用户」，可能结构性拉低客单价，因此把金额结论与转化率结论分开解读。

## 5. 样本量与 α/power 的取值

- **决策**：α=0.05、power=0.8、MDE=1pp，用两比例公式反推每组 12208 人。
- **理由**：α=0.05 与 power=0.8 是行业惯例；MDE=1pp 是「业务上值得投入改版的最小提升」。样本量由公式推导而非拍脑袋，保证实验有 80% 功效检出 1pp 的差异。

## 6. Peeking（偷看数据）的口径与量化

- **决策**：peeking 定义为「按天累计、每天做一次检验、p<0.05 就停」；用蒙特卡洛模拟量化其假阳性率。
- **理由**：模拟一个「无真实效应」的实验，每天偷看一次，实测假阳性率约 **21.9%**（远高于名义 5%），直观说明「p<0.05 就停」会放大第一类错误。这是本项目区分「会画图」与「懂统计」的关键加分项。

## 7. 多重比较：预指定 vs 探索性

- **决策**：设备（3 类）与新老用户（2 类）是**预指定**的次级假设，不做校正；城市等**探索性**分群需做 Bonferroni / FDR 校正。
- **理由**：预指定假设的检验次数有限且事先声明，假阳性风险可控；探索性分群属于「数据挖掘」，12 次检验的「至少一次假阳性」概率达 46%，必须校正。实测不做校正时有 3 个城市「偶然显著」，Bonferroni/FDR 后均被剔除——这正是多重比较要防的坑。

## 8. SRM 与平衡性的判定阈值

- **决策**：SRM 卡方 p 阈值取 0.001（而非 0.05），分流前指标平衡取 0.05。
- **理由**：SRM 是「分流机制」的硬检查，漏过它等于整个实验作废，用更严的阈值（0.001）以降低漏检风险；平衡性检查是「基线可比性」，用常规 0.05 即可。
